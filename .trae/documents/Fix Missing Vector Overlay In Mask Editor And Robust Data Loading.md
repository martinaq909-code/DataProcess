## 问题定位
- 数据集 testdata/google 下 images 与 vectors/vrts 同名匹配齐全，但部分矢量文件为空（features 数组为空），例如 `vectors/116.639099_39.959754_116.641846_39.961859.geojson`。
- 当矢量为空或不在影像范围内时，编辑器只显示图像，不会绘制道路叠加；日志出现 `[WARN] No vector geometry`。
- 其他影像在 buffers_json 中有对应参数，能正常显示道路叠加。

## 目标
- 即使矢量为空，界面要明确提示并提供可选的回退方式（例如临时从 OSM 取路网或显示 bbox 辅助轮廓）。
- 加强路径解析与加载状态可视化，让用户一眼看到当前使用的 vec/vrt/json 路径及道路统计。
- 保持现有功能与算法流程不变，增加健壮性与可视化反馈。

## 实施方案
### 1. 加载状态可视化
- 在编辑页添加状态栏，显示：
  - `Image:` 当前 `img_path`
  - `Vector:` 解析到的 `vec_path`（存在/空/要素数）
  - `VRT:` 解析到的 `vrt_path`（存在/有效 transform）
  - `JSON:` 使用的 `params.json` 路径或“无”
  - `Roads:` `road_geoms` 条数（生成的道路多边形数）
- 当 `road_geoms == 0` 时，状态栏提示“当前影像范围内没有矢量要素”，并显示可选回退建议。

### 2. 矢量为空的回退策略（可选开关）
- 在编辑页添加复选框 `Use OSM fallback when vectors empty`：
  - 当矢量为空时，使用 `core.osm_fetcher.fetch_osm_features(bbox=X)` 按影像 bbox 拉取道路，并转为道路几何进行叠加（只读缓存，不保存到原 vectors）。
  - 生成的叠加仅用于可视化与参数编辑，不改变原始数据集。（确保不改变功能的核心输出逻辑）

### 3. 数据加载健壮性
- JSON 加载：若 `roads[*].geometry_wkt` 缺失，自动从矢量文件重建 `road_geoms`。
- 路径解析：继续保留多候选解析顺序（vectors/vrts/buffers_json），并在状态栏呈现最终选中的路径。
- 首次生成道路多边形时：若某条路缺少 `road_params` 项，自动补齐默认宽度（左右 10px），确保绘制。

### 4. 工具脚本用于数据自检（只读）
- 提供一个只读的检测脚本，统计指定数据集下：
  - `images` 数量
  - `vectors` 同名存在数量与空文件数量
  - `buffers_json` 可用数量
- 输出一份报告，方便用户事先发现“矢量为空”的 tile 列表。

### 5. 验证
- 使用 `testdata/google` 数据集逐张验证：
  - 有 JSON 的：应正常显示道路叠加
  - 无 JSON 但有矢量的：应正常叠加道路（通过从矢量生成）
  - 矢量为空：应显示提示；若开启回退，则叠加 OSM 道路

### 6. 不影响现有功能
- 不改变 `process_single_pair_full_improved` 和 Buffer 编辑保存逻辑，只增广加载层的健壮性与可视化反馈。
- 所有新增功能通过界面选项或状态显示提供，不强制改变现有流程。
