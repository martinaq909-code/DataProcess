## 🚀 多进程优化特性

### 1. 自动并行化
```python
NUM_WORKERS = max(1, cpu_count() - 1)  # 自动使用CPU核心数-1
```
- 自动检测CPU核心数
- 默认使用 **核心数-1** 个worker（留一个给系统）
- 您的系统将使用 **19个并行worker**

### 2. 实时进度监控
```
[Progress] 10/2346 (0%) - Elapsed: 0.3min, ETA: 70.2min
[Progress] 20/2346 (1%) - Elapsed: 0.6min, ETA: 69.5min
...
```
- 每完成10个任务报告一次
- 显示已用时间和预计剩余时间
- 动态更新ETA

### 3. 智能任务分配
- 使用 `Pool.imap_unordered` 实现动态任务分配
- 先完成的worker立即接收新任务
- 负载均衡，避免某些worker空闲

### 4. 异常处理
```python
try:
    result = process_single_pair(...)
    return (True, result)
except Exception as e:
    print(f"[ERROR] {base}: {str(e)}")
    return (False, None)
```
- 单个图像失败不影响整体处理
- 错误信息实时显示
- 继续处理其他图像

## 🎛️ 配置选项

### 调整Worker数量

**默认配置**（推荐）:
```python
NUM_WORKERS = max(1, cpu_count() - 1)  # 自动检测
```

**手动设置**:
```python
# 使用所有核心（不推荐，会影响系统响应）
NUM_WORKERS = cpu_count()

# 保守设置（系统负载高时）
NUM_WORKERS = cpu_count() // 2

# 调试模式（单进程，便于调试）
NUM_WORKERS = 1
```

### 内存考虑

每个worker会占用内存：
- 图像加载: ~10-20 MB/worker
- 缓存系统: ~5-10 MB/worker
- 总计: ~15-30 MB/worker

**您的系统**: 19 workers × 25 MB ≈ **475 MB** (完全可接受)

如果内存不足，可以减少worker数量：
```python
NUM_WORKERS = 8  # 手动限制
```

## ⚠️ 注意事项

### 1. 打印信息交错

多进程模式下，各个worker的打印信息可能会交错显示：
```
============================================================
Processing: 116.614380_39.890246_116.617126_39.892353
============================================================
============================================================
Processing: 116.650085_39.921849_116.652832_39.923956
============================================================
```

这是正常现象，不影响处理结果。

### 2. 中途停止

可以随时按 `Ctrl+C` 停止处理：
- 已完成的文件会保存
- 正在处理的文件可能不完整
- 可以重新运行（会覆盖或继续）

确保有足够空间：
- 2346张图像 × ~1.5 MB = ~3.5 GB（JPG）
- 2346张mask × ~0.5 MB = ~1.2 GB（PNG）
- 总计: ~5 GB

## 🔧 技术细节

### 多进程实现

```python
from multiprocessing import Pool, cpu_count

def process_worker(args):
    """Worker函数，每个进程执行"""
    img_path, vec_path, vrt_path, output_dir, params = args
    try:
        result = process_single_pair(...)
        return (True, result)
    except Exception as e:
        return (False, None)

# 主函数中
with Pool(processes=NUM_WORKERS) as pool:
    for success, result in pool.imap_unordered(process_worker, tasks):
        # 处理结果
        ...
```

### 优化要点

1. **独立任务**: 每个图像的处理完全独立
2. **无共享状态**: 每个进程有自己的缓存
3. **动态分配**: 使用 `imap_unordered` 而非 `map`
4. **错误隔离**: 单个失败不影响整体

### 为什么不用多线程？

Python的GIL（全局解释器锁）限制：
- **多线程**: 受GIL限制，CPU密集型任务提升有限（~1.2-1.5倍）
- **多进程**: 每个进程独立，完全并行（~核心数倍）

对于CPU密集型的图像处理任务，多进程是最优选择。
